# 光速上升设计风格说明

本文档是前端视觉实现的参考标准。后续所有页面、组件和改版都应优先遵守这里的规则，再去补充局部细节。

## 1. 设计方向

整体气质是“克制、策展感、深色品牌站”，不是常规电商模板，也不是信息表格站。

- 页面基调偏深色，采用低饱和背景和暖金色强调。
- 版面强调层级和留白，避免密集堆叠。
- 大标题要有识别度，正文要稳定可读。
- 卡片和面板要有明确的层次分隔，不能全靠边框硬切。

## 2. 唯一设计值来源

所有设计值统一从 `src/theme/tokens.js` 读取，不允许在页面里随手写一套新的视觉数值。

允许从 tokens 获取的内容包括：

- 颜色
- 渐变
- 圆角
- 阴影
- 间距
- 字号
- 动效时长

如果某个场景需要新的视觉值，先补到 tokens，再在组件里使用。

## 3. 推荐视觉语义

### 颜色

- 页面背景使用深色 canvas。
- 主卡片使用更高一阶的 surface。
- 强调色使用暖金和偏棕金，不要改回紫色系。
- 次级信息使用低对比度文字，不要把所有文字都写成同一种白色。

### 圆角

- 最高层容器可以更大，形成柔和的画面边界。
- 卡片、按钮、图片容器、标签的圆角要分层，不能全站一个值。
- 交互控件建议使用胶囊形或接近胶囊形的圆角。

### 阴影

- 阴影只用于强调层级，不作为装饰噪音。
- 悬浮卡片、主按钮、重要面板可以使用更明显阴影。
- 小组件尽量轻阴影或无阴影，保持画面干净。

### 版式

- 页面左右留白要统一，不要每页随意变。
- 区块之间留足垂直间距，保证章节感。
- 组件内边距要稳定，不要在同类卡片之间来回跳。

### 字体

- 标题使用稳定的中文无衬线栈，保留粗重层级。
- 正文和辅助信息要保证可读性，避免过细字重。
- 英文专有名可以保留原样，但不能让英文成为主视觉默认语言。

### 动效

- 过渡要短促、克制，避免夸张弹跳。
- 适合用淡入、轻微上移、缩放反馈，不要堆叠太多微动效。
- 页面加载和切换要有层次，但不能打断阅读。

## 4. 页面内容规范

- 导航、按钮、提示、空态、筛选、页脚、元信息都应中文化。
- 只保留品牌名、型号名、案例专有名和数据 id 的英文形式。
- `alt`、可访问性文本、分享标题也属于页面文案，必须同步中文化。

## 5. 组件写法规范

- 先引用 tokens，再写结构。
- 共享布局优先复用，不要复制页面级壳层。
- 新增页面先确认是否能复用现有卡片、标题、筛选、页脚、导航组件。
- 不要在单个页面里重新定义整套颜色、圆角、阴影和间距。

## 6. 新增页面流程

1. 先确认页面属于哪个 hash 路由。
2. 先查看是否已有可复用的内容数据和共享组件。
3. 优先使用 `src/theme/tokens.js` 里的值。
4. 再补页面结构和局部交互。
5. 最后做中文化检查和无头验证。

## 7. 反模式

以下做法默认视为错误：

- 页面内直接写新的品牌色值而不进入 tokens。
- 同类按钮、卡片、标题在不同页面里长得完全不一样。
- 页面里继续保留通用英文 UI 文案。
- 为了“看起来像”而随手堆砌多种圆角、阴影和渐变。
- 为某个页面临时造一套只用一次的设计规则。

## 8. 参考文件

- `src/theme/tokens.js`
- `src/data/siteContent.js`
- `src/components/`
- `src/App.jsx`

这些文件共同构成当前前端的视觉与内容基线。后续新增页面必须在此基线上扩展，而不是绕开它重新写一套。
