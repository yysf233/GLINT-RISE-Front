# Share Landing Pages Design

**Date:** 2026-03-23

## Goal
补齐公开站“分享落地页（项目 / 产品）”能力，让产品与案例在微信、QQ、钉钉等场景中被分享后，落到专门的移动端优先公开页面，而不是继续直接落到当前详情页路由。

## Approved Direction
- 新增两个独立公开路由：
  - `#/share/product/:id`
  - `#/share/case/:id`
- 产品详情页和案例详情页的分享按钮改为分享对应的独立落地页链接
- 独立分享页只展示公开字段，不引入后台字段、内部字段或任何鉴权逻辑
- 分享页保留明显 CTA，允许用户从分享页继续进入官网详情页
- 案例图谱页暂不拆独立分享页，继续保留页面级分享

## Scope
本次只处理公开站的分享落地页，不做分享短链服务、不做失效控制、不做服务端签名、不做分享数据统计后台。

本次范围包括：
- 新增产品分享落地页
- 新增项目分享落地页
- 新增用于生成分享链接的轻量工具
- 更新产品详情页与案例详情页的分享按钮行为
- 更新 `PRJ_PRD.md` 的进度状态
- 更新自动验收脚本，覆盖两个分享落地页路由

## Information Architecture
- 产品详情页：`#/product/:id`
- 产品分享页：`#/share/product/:id`
- 案例详情页：`#/case/:id`
- 案例分享页：`#/share/case/:id`

页面关系：
- 详情页负责完整浏览
- 分享页负责外部传播落点
- 分享页内提供 “进入官网详情” 入口

## Page Structure
### 产品分享页
- 主图
- 产品名 / 标签 / 简述
- 公开元信息摘要
- “进入官网详情”按钮
- 品牌与分享提示

### 项目分享页
- 主图
- 项目标题 / 时间标签 / 摘要
- 公开项目信息摘要
- “进入官网详情”按钮
- 品牌与分享提示

## Behavior
- 详情页点击分享时，不再复制当前详情路由，而是复制对应分享页路由
- 在支持 `navigator.share` 的环境中优先调用系统分享
- 不支持时回退到复制分享落地页 URL
- 分享页本身仍然是公开站 Hash 路由，可刷新、可直接打开、可移动端访问

## Data And Security
- 复用现有 `products` 与 `cases` 内容数据
- 只读取当前公开详情页已展示过的公开字段
- 不新增任何内部字段映射
- 不让分享页成为后台入口

## Verification
- `npm run build`
- `npm run verify:routes -- http://127.0.0.1:4173`

新增验收重点：
- `#/share/product/:id` 可访问
- `#/share/case/:id` 可访问
- 分享页存在进入官网详情页的 CTA
- 产品 / 案例详情页分享行为使用分享落地页 URL

## Risks And Constraints
- 目前分享基于 HashRouter，外部平台打开链接时需要保持当前静态部署方式兼容
- 分享页如果直接复用过多详情页结构，会削弱“落地页”意义；应保持更轻、更聚焦
- 分享页必须继续受公开字段边界约束，不能因为复用详情页组件而意外暴露内部信息
