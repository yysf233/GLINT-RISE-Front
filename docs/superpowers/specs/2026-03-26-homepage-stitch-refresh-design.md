# 首页 Stitch 改版设计
**日期：** 2026-03-26

## 背景

Stitch 中的首页高保真原型已经更新，目标 screen 为：

- 项目：`projects/15241179983541341880`
- 目标 screen：`projects/15241179983541341880/screens/aedc6f43d62c49b48ff6c52e6bd73dcf`

当前线上实现仍然延续上一版首页结构：

- Hero 为左文案右球体的双栏构图
- 案例区为双大卡聚焦
- 热门产品区为四卡轮播
- 品牌故事区为较重的拼贴模块

这些结构与新版 Stitch 首页不一致。新版原型的视觉特征更克制，信息层级也明显收缩：

- 顶部为更轻的扁平导航条
- Hero 改成居中品牌构图
- 案例区改成左右预览 + 中间主卡的三栏舞台
- 热门产品区改成三张大卡陈列
- 页脚收敛为单行轻量信息带

本次改版只处理首页和首页直连的公共壳层表现，不改动其他公开页的结构。

## 目标

在保留现有动态数据能力的前提下，把首页重构为接近新版 Stitch 原型的深色品牌首页，同时满足以下约束：

- Header 保持中文导航，不跟随 Stitch 原型回退到英文
- 首页搜索仍然跳转到现有搜索结果页
- 案例卡和产品卡仍然跳转到现有详情页
- 首页继续优先读取公共站点配置、首页 banner、案例数据和产品数据
- 轮播仍然保留现有 Apple 风格交互能力，但首页默认展示形态要先服从新版布局

## 非目标

- 不调整其他公开页布局
- 不重构后台配置模型
- 不新增首页编辑能力
- 不重新定义全站设计系统

## 目标原型拆解

### 1. 顶部导航

新版原型的导航条更轻，横向留白更大，品牌和主导航都更贴近页面顶边。

实现要求：

- 保留现有公共 `TopNav` 组件入口
- 首页使用更扁平、更简洁的深色样式变体
- 导航文案保持中文
- 右上角主按钮视觉改成浅紫色胶囊按钮，贴近 Stitch 原型

### 2. Hero

Hero 改为居中舞台，不再使用右侧大球体作为主要构图。

实现要求：

- 主标题采用“光速上升 / GLINT RISE”居中双层排版
- 标题上方增加小型品牌装饰符号
- 标题下方增加细分隔线和微装饰点
- 搜索条置于 Hero 中央偏下位置，宽度接近原型
- 背景保留深色科技氛围，但不能再是旧版大面积球体主视觉

内容策略：

- 中文主标题固定展示 `siteSettings.brand.cnName`
- 英文副标题展示 `siteSettings.brand.name`
- Hero 说明文案允许使用首页本地兜底文案，不强依赖旧版长段描述

### 3. 案例区

案例区改成三栏舞台：

- 左右为预览卡
- 中间为强调主卡
- 区块顶部左侧为小眉标题 + 主标题，右侧为“查看更多”

实现要求：

- 默认展示 3 个案例
- 中间卡视觉最突出，宽度显著大于左右卡
- 左右卡作为预览态，可点击切换焦点或直接跳详情
- 轮播/切换能力保留，但呈现要优先服务新版三栏布局

### 4. 热门产品区

热门产品区改成三张高卡片陈列，而不是上一版的四卡滚动货架。

实现要求：

- 默认展示 3 个产品
- 中间产品卡为强调态，可出现徽标或按钮
- 左右卡为普通态
- 保留点击跳产品详情
- 保留轮播能力，但默认视图必须是三卡布局

### 5. 页脚

页脚要压缩成原型那种轻量信息带，而不是上一版较重的品牌拼贴尾区。

实现要求：

- 顶层品牌名、版权和辅助链接放在一行或两行轻量布局中
- 保留站点设置里的 footer link 数据
- 视觉上与首页深色背景融为一体

## 数据与映射策略

### 案例

- 继续使用 `cases` 数据源
- 首页按既有优先级挑选 3 个案例
- 若案例不足 3 个，则按现有顺序兜底

### 产品

- 继续使用公共产品目录
- 首页按公开产品顺序挑选 3 个产品
- 若产品不足 3 个，则按可用数量展示，不补空卡

### 搜索

- 保留现有 `SearchBar` 交互和搜索页跳转逻辑
- 允许根据原型需要对输入框布局、尺寸和视觉样式做首页专用收边

## 组件边界

### `HomePage`

负责：

- 新版首页布局编排
- Hero、案例区、产品区的数据选择和首页态展示
- 首页专属轮播挂接

### `TopNav`

负责：

- 首页专用轻量深色头部变体
- 中文导航标签
- 右上角主按钮的原型化视觉

### `Footer`

负责：

- 首页底部信息带压缩样式
- 继续承接现有 footer 数据

## 交互策略

- 继续沿用现有 Apple 风格自动播放、悬停暂停和手动接管机制
- Hero 不再强调大面积背景轮播视觉，只保留低干扰动态氛围
- 案例区和产品区允许自动切换，但动画幅度要收敛，避免破坏新版极简舞台感
- 如果 `prefers-reduced-motion` 启用，则退化为静态切换

## 测试策略

先改测试，再改实现。首页测试需要锁定新版结构，而不是旧版双栏 Hero。

最低验证范围：

- `src/pages/HomePage.test.jsx`
  - 新首页根布局标记存在
  - 居中 Hero 结构存在
  - 三栏案例舞台标记存在
  - 三卡产品舞台标记存在
  - 轻量 footer 结构存在
- 如头部或页脚增加新结构标记，再补对应组件测试

实现后执行：

- `npm run test:unit -- src/pages/HomePage.test.jsx`
- `npm run test:unit`
- `npm run build`

## 风险

### 1. 原型更像静态品牌页，现有首页更像动态门户

处理方式：

- 优先服从新版布局
- 保留数据源和跳转能力
- 弱化但不删除动态能力

### 2. 中文导航与 Stitch 英文导航存在偏差

处理方式：

- 以用户要求为准，首页头部文案保持中文
- 只复刻布局、间距和控件造型，不强行复制英文文案

### 3. 首页模块删减可能影响旧测试和旧视觉钩子

处理方式：

- 用新版结构测试替换旧断言
- 只保留仍然服务新版布局的测试钩子
