# 后台 Ant Design 化与第一波业务闭环设计

## 目标

本次设计要解决的不是单纯的后台换皮，而是把当前已经存在的 mock 后台壳层重构为一套可复用的 Ant Design 风格后台系统，并在同一轮内完成第一波核心业务闭环。

本次设计固定 3 个结果：
- 后台页面整体改为 Ant Design 风格，信息架构参考 Stitch 中的“内部工作台”“库存仪表盘”“产品新增与编辑”等原型。
- 公共组件必须先抽离，后续后台模块不得继续用一次性页面结构堆叠。
- 第一波必须跑通 3 条完整业务链：产品上架、项目上架、首页轮播图管理与图片排序。

## 背景与约束

当前仓库已经具备：
- 公开站主链路
- `#/login` mock 认证
- `#/workspace/*` 受保护后台路由
- 产品管理 mock 模块第一版

但当前后台仍存在以下问题：
- 视觉体系延续公开站品牌风格，不符合常规后台使用场景
- 左侧导航和页面结构偏占位，无法承接后续大规模后台模块
- 产品模块虽然已具备功能，但组件未抽象，不适合作为后续模块的复用基座
- `PRJ_PRD.md` 中仍有大量后台待开发事项，需要用“可分波次推进”的方式持续回填

用户额外确认的强约束如下：
- 只改登录后的后台页面，不改 `#/login`
- 允许按 Stitch 原型重排后台导航与信息架构
- 页面上的文字，除业务专有名词外，统一使用中文
- 必须保证功能交互和业务流程完整，不接受只有页面壳层
- 每一波完成后必须同步回填 `PRJ_PRD.md`

## 分波策略

本次后台重构不按“一个大版本一次做完”推进，而按波次拆分。

### 第 0 波：后台 Ant Design 基座

目的：
- 统一后台布局、导航、页面骨架和状态反馈
- 把后续模块会重复使用的页面结构抽成公共组件

交付内容：
- 新的后台布局壳层
- 分组侧边导航
- 顶部工具区
- 页面标题区、统计区、筛选区、表格区、详情区、表单区、步骤区
- 空态、错误态、无权限态、成功反馈等统一状态组件

### 第 1 波：核心业务闭环

目的：
- 在新后台基座上完成第一批最关键且能直接回填 PRD 的业务闭环

固定包含：
- 产品上架闭环
- 项目上架闭环
- 首页轮播图管理闭环

### 后续波次

本设计只详细规定第 0 波和第 1 波。后续波次按本设计的基座继续推进：
- 第 2 波：供应商管理闭环
- 第 3 波：询价与导出闭环
- 第 4 波：高权限系统闭环

## 信息架构重排

后台整体导航按业务分组重排，不继续沿用当前“按角色硬编码少量入口”的导航结构。

### 一级导航分组

- 工作台
  - 仪表盘
- 商品与项目
  - 产品管理
  - 项目管理
  - 轮播与推荐
- 采购与导出
  - 供应商管理
  - 询价流程
  - 导出中心
- 系统管理
  - 内容管理
  - 权限与用户
  - 日志与监控

### 第 1 波实际落地路由

本轮需要真正落地并可访问的后台路由：
- `#/workspace/dashboard`
- `#/workspace/products`
- `#/workspace/products/new`
- `#/workspace/products/:productId`
- `#/workspace/products/:productId/edit`
- `#/workspace/products/import`
- `#/workspace/projects`
- `#/workspace/projects/new`
- `#/workspace/projects/:projectId`
- `#/workspace/projects/:projectId/edit`
- `#/workspace/content/banners`
- `#/workspace/content/banners/new`
- `#/workspace/content/banners/:bannerId/edit`
- `#/workspace/forbidden`

第 2 波以后的导航入口可以先存在，但若页面未落地，必须进入统一的“待开发”状态页，而不是保留无说明的空白占位。

“待开发”状态页的固定行为：
- 允许保留真实目标路由，便于导航结构提前稳定
- 页面主体使用统一 `AdminResultState`
- 必须明确展示“模块待开发”说明、预计所属波次、返回仪表盘入口
- 路由验收时，只验证其为可解释的待开发状态，不视为功能已完成

## 视觉与布局方向

后台视觉语言采用 Ant Design 常见的企业后台风格，不再延续公开站的深色品牌表达。

固定方向：
- 主色使用冷静的蓝灰体系，局部操作色使用 Ant Design 风格高亮蓝
- 页面背景以浅灰和白色卡片为主
- 布局采用“左侧固定导航 + 顶部工具区 + 主工作区”
- 表格、表单、步骤流、抽屉、标签、状态徽标、结果反馈等全部向 Ant Design 后台使用习惯靠拢

参考原型映射：
- 仪表盘与壳层：参考 Stitch “内部工作台（业务总监版）”
- 统计区与表格密度：参考 Stitch “库存仪表盘”
- 表单结构：参考 Stitch “产品新增与编辑”
- 详情页区块结构：参考 Stitch “产品详情页（内部/高权限版）”

说明：
- 允许直接借鉴 Stitch 原型的布局、分区和层级关系
- 但最终代码必须补全真实交互、权限控制、状态变化和反馈逻辑

## 公共组件边界

第 0 波必须优先抽出以下公共组件，后续后台页面只能基于这些组件或其组合继续扩展。

### 布局类组件

- `AdminLayout`
  - 后台总壳层，负责侧边导航、顶部工具区、面包屑与工作区容器
- `AdminSiderNav`
  - 左侧导航分组、当前路由高亮、角色可见性控制
- `AdminTopbar`
  - 顶部全局搜索、角色标识、返回官网、退出登录
- `AdminPageHeader`
  - 页面标题、副标题、主操作按钮、辅助操作按钮

### 页面结构类组件

- `AdminStatsRow`
  - 统计卡区
- `AdminFilterBar`
  - 搜索、筛选、排序、快捷操作
- `AdminTableCard`
  - 表格容器、批量操作栏、分页或结果统计
- `AdminDetailSection`
  - 详情页区块容器
- `AdminFormSection`
  - 表单区块容器
- `AdminStepShell`
  - 多步骤流程容器

### 业务能力类组件

- `AdminUploadPanel`
  - 媒体上传、封面选择、替换逻辑
- `AdminSortableMediaList`
  - 图片顺序调整，支持拖拽或显式上移下移
- `AdminResultState`
  - 空态、错误态、成功态、发布结果态
- `PermissionGuardNotice`
  - 无权限与角色限制说明

### 组件设计要求

- 组件要围绕“页面骨架”抽象，不抽无意义的小碎片
- 每个组件要有清晰职责，不同时承担布局、数据请求、业务判断
- 业务页只负责组装数据与交互，不重复定义布局模式

## 数据层设计

当前已有的产品 mock 服务要提升为统一后台 mock 数据层的一个子模块，第 1 波新增项目与轮播配置的数据子模块。

建议结构：
- `src/services/workspace/`
  - `workspaceProductsApi.js`
  - `workspaceProjectsApi.js`
  - `workspaceBannersApi.js`
- `src/services/mock/`
  - `mockWorkspaceProductsService.js`
  - `mockWorkspaceProjectsService.js`
  - `mockWorkspaceBannersService.js`
- `src/data/workspace/`
  - `workspaceProductSeeds.js`
  - `workspaceProjectSeeds.js`
  - `workspaceBannerSeeds.js`

规则：
- 所有 mock 服务统一返回 Promise
- 所有新增、编辑、排序、发布操作都要写入本地持久化存储
- 刷新页面后，已完成的操作结果必须仍可回查
- 公开站预览页读取时，要能映射到后台最新 mock 状态

持久化归属规则：
- 产品、项目、轮播各自拥有独立的存储 key 和 schema
- 公共层只抽持久化读写 helper，不混合不同模块的数据结构
- 公开站读取后台结果时，通过单独的映射层转换，不直接复用后台 schema

## 权限模型

本轮继续沿用当前的 3 角色：
- 员工
- 总监
- 开发者

### 第 1 波权限规则

员工与总监：
- 可访问仪表盘
- 可访问产品管理、项目管理、轮播配置

开发者：
- 保留后台入口与受保护路由能力
- 对第 1 波的产品、项目、轮播页面默认无权限
- 访问这些页面时进入统一无权限页

说明：
- 本轮不展开复杂字段级权限矩阵
- 但页面级路由控制必须完整
- 第 4 波再把权限管理页与更细粒度控制补齐

## 第 1 波业务闭环

### 一、产品上架闭环

#### 页面范围

- 产品列表页
- 产品详情页
- 产品新增页
- 产品编辑页
- 产品批量导入页

#### 业务步骤

1. 在产品列表页创建产品，填写基础信息、分类、标签、价格、展示文案、内部说明。
2. 上传产品图片，并设置封面与图片顺序。
3. 保存为草稿后，可进入详情页查看状态、日志、同步状态。
4. 从列表页或详情页切换产品状态：草稿、已上架、已下架。
5. 上架后可跳转公开站产品页进行预览。
6. 通过批量导入进入系统的产品，也能继续编辑并完成上架。

#### 关键交互要求

- 搜索、筛选、排序、批量加标签继续保留
- 图片顺序变更必须可视化且能持久化
- 上架状态变化必须有明确反馈
- 详情页要可回查最近一次关键操作

### 二、项目上架闭环

#### 页面范围

- 项目列表页
- 项目详情页
- 项目新增页
- 项目编辑页

#### 业务步骤

1. 创建项目，填写标题、摘要、行业、品牌、封面图、分享图。
2. 维护项目时间轴节点、正文模块与关联产品。
3. 设置公开展示开关与推荐信息。
4. 保存草稿后进入详情页检查结构。
5. 提交上架后可跳转公开案例详情与时间轴相关页面进行预览。
6. 项目下架后不再出现在公开站入口中。

#### 关键交互要求

- 时间轴节点必须支持新增、编辑、删除和排序
- 关联产品必须从后台产品数据中选择
- 封面图、分享图支持替换
- 项目上架状态要与公开站映射

### 三、首页轮播图管理闭环

#### 页面范围

- 轮播图列表页
- 轮播图新增页
- 轮播图编辑页

#### 业务步骤

1. 查看当前首页轮播列表。
2. 新增轮播项，上传图片，填写标题、副标题、跳转目标。
3. 编辑已有轮播项内容与图片。
4. 调整轮播项顺序。
5. 执行上下线控制。
6. 发布后跳到首页进行预览。

#### 关键交互要求

- 顺序调整结果必须可回显且持久化
- 跳转目标必须校验为有效站内路由
- 下线轮播不得继续显示在首页
- 发布动作必须有成功或失败反馈

## 文案规则

后台页面文案默认全部改为中文。

允许保留英文的范围：
- 技术与系统专有名词，例如 SKU、ID、API、Mock
- 业务字段原值本身即为英文

不允许继续保留当前这类英文后台文案：
- Workspace Overview
- Product Operations
- Content Maintenance
- Logging Out

## 测试与验收设计

本次不是做完页面即结束，必须同步完成测试标准。

### 单元测试

至少覆盖以下逻辑：
- 产品、项目、轮播数据服务的新增、编辑、删除、排序、发布逻辑
- 产品图片排序逻辑
- 项目时间轴节点排序与关联产品逻辑
- 轮播图排序与路由校验逻辑
- 权限辅助判断逻辑

### 路由与交互验收

扩展现有 `scripts/verify-pages.mjs`，至少覆盖：
- 员工、总监可进入产品、项目、轮播管理页面
- 开发者访问这些页面被正确拦截
- 产品新增后可进入详情页并切换状态
- 产品图片顺序调整后，详情页和公开预览顺序一致
- 项目新增后可进入详情页并维护时间轴
- 项目上架后可从公开站相关入口访问
- 轮播图排序与上下线后，首页展示同步变化
- 所有关键保存、发布动作都有明确反馈

### 构建与回归

每一轮都必须通过：
- `npm run test:unit`
- `npm run build`
- `npm run verify:routes -- <preview-url>`

## PRD 回填规则

`PRJ_PRD.md` 不在最后统一补，而是作为每一波的必做项。

第 0 波完成后需要回填：
- 工作台 / 仪表盘：从“进行中”更新为“已完成”或更准确状态
- 后台视觉和结构升级说明
- 公共组件与测试标准

第 1 波完成后需要回填：
- 产品管理相关条目为最新状态
- 项目管理相关条目为最新状态
- 轮播图管理相关条目为最新状态
- 每条条目附带“当前结果”“下一步动作”“测试标准”

## 非目标

本设计当前不包含：
- 登录页重做
- 真实后端 API
- 供应商管理模块完整实现
- 询价 5 步流程实现
- 导出中心实现
- 用户与权限配置页实现
- 审计日志与监控页实现

这些内容属于后续波次，不进入当前实现计划。

## 通过标准

当本设计对应实现完成时，必须满足以下条件：

1. 登录后的后台页面整体切换到统一 Ant Design 风格。
2. 后台壳层、导航、页面结构公共组件已经抽离，不再依赖一次性页面结构。
3. 产品上架闭环可完整演示。
4. 项目上架闭环可完整演示。
5. 首页轮播图管理与图片排序闭环可完整演示。
6. 员工、总监、开发者三种角色的访问限制符合设计。
7. 后台通用文案已中文化。
8. `PRJ_PRD.md` 已按波次回填。
9. 单元测试、构建、路由验收全部通过。
