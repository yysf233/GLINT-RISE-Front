# 统一分享面板设计
**日期：** 2026-03-26

## 背景

当前公开页的分享按钮统一走 [shareCurrentPage.js](C:/Users/23271/Desktop/光速上升/front/src/utils/shareCurrentPage.js)：

- 优先调用 `navigator.share`
- 否则复制链接
- 没有渠道选择界面

新增要求是：

- 所有分享按钮统一替换成渠道选择面板
- 渠道至少包含 QQ、微信、钉钉
- 用户点击后优先直接在对应软件中打开，而不是默认跳浏览器落地页

## 技术边界

普通浏览器对 QQ / 微信 / 钉钉的“直接拉起客户端并预填分享内容”支持并不对称，因此实现采用环境分级策略：

- 微信内：优先接入微信环境分享能力
- 钉钉内：优先接入钉钉环境分享能力
- 普通浏览器：优先尝试对应客户端 scheme / 深链唤起；若失败则降级为系统分享、复制链接或二维码提示

该策略以“最大化直达客户端”为目标，但不承诺所有桌面浏览器都能稳定无跳转完成唤起。

## 目标

- 所有公开页分享按钮统一改为打开分享面板
- 面板提供 QQ、微信、钉钉三种渠道
- 在支持环境中尽量直接走对应客户端分享
- 在不支持环境中提供明确降级路径，不让按钮失效

## 非目标

- 不接入复杂的社交统计上报
- 不实现平台 OAuth 登录
- 不承诺浏览器外部协议在所有设备和浏览器都完全一致

## 交互设计

### 分享按钮行为

- 点击分享按钮，不再立即调用 `navigator.share`
- 改为打开统一分享面板

### 分享面板内容

- 标题：如“选择分享渠道”
- 渠道项：
  - QQ
  - 微信
  - 钉钉
- 辅助操作：
  - 复制链接
  - 取消 / 关闭

### 选择渠道后的行为

- 微信环境内：
  - 优先配置微信分享数据
  - 提示用户通过微信原生分享入口完成发送
- 钉钉环境内：
  - 优先调用钉钉分享能力
- QQ 环境内：
  - 优先尝试 QQ 客户端可用的分享唤起或分享链接
- 普通浏览器：
  - 优先尝试渠道 scheme 唤起
  - 唤起失败时降级到系统分享或复制链接

## 环境决策表

### 微信内

- 可见渠道：微信、QQ、钉钉、复制链接
- 点击微信：
  - 配置微信分享数据
  - 提示使用微信右上角原生分享入口
- 点击 QQ / 钉钉：
  - 尝试 scheme 唤起
  - 失败后回退到复制链接

### 钉钉内

- 可见渠道：钉钉、微信、QQ、复制链接
- 点击钉钉：
  - 优先调用钉钉环境分享能力
- 点击微信 / QQ：
  - 尝试 scheme 唤起
  - 失败后回退到复制链接

### QQ 内

- 可见渠道：QQ、微信、钉钉、复制链接
- 点击 QQ：
  - 优先尝试 QQ 环境可用的分享能力或客户端唤起
- 点击微信 / 钉钉：
  - 尝试 scheme 唤起
  - 失败后回退到复制链接

### 普通浏览器

- 可见渠道：QQ、微信、钉钉、复制链接
- 点击 QQ / 微信 / 钉钉：
  - 先尝试对应 scheme / 深链唤起
  - 若浏览器支持 `navigator.share`，则作为第二优先级回退
  - 若 `navigator.share` 不可用，则回退到复制链接
- 点击复制链接：
  - 直接复制当前分享链接

最终兜底规则：

- 所有渠道失败时，至少保证复制链接成功或给出明确失败提示
- 不允许按钮点击后无反馈

## 架构设计

## 风险

### 1. 外部应用协议可能被浏览器拦截

处理方式：

- 将“客户端直开”定义为优先策略，不定义为绝对成功条件
- 所有渠道都必须有可用降级路径

### 2. 微信分享在非微信环境中能力受限

处理方式：

- 仅在微信 WebView 内启用微信环境分支
- 其他环境使用复制链接 / 系统分享 / scheme 尝试
