# 横向案例时间轴设计
**日期：** 2026-03-26

## 背景

当前公开页 [CaseTimelinePage.jsx](C:/Users/23271/Desktop/光速上升/front/src/pages/CaseTimelinePage.jsx) 仍然是“左侧说明栏 + 右侧纵向分段卡片列表”的结构：

- 时间轴按分段竖向堆叠
- 只支持缩放，不支持拖拽平移
- 页面直接依赖静态 `cases` 数据
- 后台项目表单里的时间轴字段只适合内部阶段说明，不足以驱动公开页横向时间轴

目标原型要求改为更接近信息地图的横向时间轴：

- 从左到右表示从过去到现在
- 同时有年度大刻度和季度细刻度
- 每个项目从主轴节点延伸引线连接到项目简介卡片
- 画布支持横向拖拽、鼠标缩放和右下角缩放控件
- 时间轴内容必须可在后台设置和编辑

## 目标

重构公开案例时间轴页，使其满足以下要求：

- 时间轴改为横向布局，方向为从左到右、从过去到现在
- 轨道按年度与季度生成节点刻度
- 公开项目节点通过引线连接到上方或下方的简介卡片
- 画布支持拖拽平移、滚轮缩放、按钮缩放和缩放重置
- 时间轴公开内容不再直接读取静态 `cases`，改为读取后台项目管理里“已发布项目”
- 后台项目管理可以配置时间轴定位字段，驱动公开时间轴排序与卡片位置

## 非目标

- 不新增独立“时间轴内容管理”模块
- 不重构案例详情页和案例总览页的整体结构
- 不做复杂筛选体系，只保留原型要求的轻量 tab/状态文案

## 数据源设计

### 公开页数据源

公开时间轴页改为读取后台项目记录，而不是静态 `cases`：

- 数据源：`workspace projects`
- 公开条件：`status` 为 `active` 或与公开发布等价的状态
- 跳转目标：优先使用 `publicCaseId` 跳转到公开案例详情页

前台时间轴展示项至少需要这些字段：

- `id`
- `title`
- `summary` / `short`
- `industry`
- `category`
- `publicCaseId`
- `timelineYear`
- `timelineQuarter`
- `timelineOrder`
- `timelineCardSide`
- `timelineAccent`

### 时间轴轨道生成

时间轴轨道不依赖“每个季度一定有项目”。

规则：

- 排序唯一规则：
  - 优先使用 `timelineOrder`
  - 若 `timelineOrder` 缺失，则按 `timelineYear + timelineQuarter` 推导
  - `timelineQuarter` 映射为 `Q1=01`、`Q2=02`、`Q3=03`、`Q4=04`
  - 若两者都缺失，该项目不进入公开时间轴
- 同一季度内有多个项目时：
  - 它们共享同一个季度刻度
  - 卡片按 `timelineAccent` 优先级、再按标题字典序稳定排序
  - 上下侧位置优先使用 `timelineCardSide`
  - 若 `timelineCardSide` 缺失，则默认按同季度内顺序做 `above / below / above / below` 交错展开
  - 若多个项目声明了同一侧且发生遮挡风险，则保留首个声明项目，其余项目按交错规则回退到另一侧
  - 若 `timelineAccent` 缺失，则按普通项目处理；若同季度存在多个强调项目，则仅首个保留强调态，其余降级为普通态
- 根据所有已发布项目的 `timelineOrder` 找出起止时间
- 在起止时间之间自动补齐缺失季度刻度
- 年度节点显示大标记
- 季度节点显示细标记
- 没有项目的季度只渲染空刻度，不生成项目卡

### 与静态案例数据的关系

- 时间轴页公开内容不再直接使用 `cases`
- 但项目卡点击后仍然通过 `publicCaseId` 跳到现有案例详情页
- 若项目缺少 `publicCaseId`，则卡片不跳转，只显示禁用态或无链接态

## 后台模型设计

### 项目表单新增字段

在现有项目管理模型基础上补充公开时间轴定位字段：

- `timelineYear`: 字符串，例如 `2024`
- `timelineQuarter`: 枚举，`Q1 | Q2 | Q3 | Q4`
- `timelineOrder`: 数值，例如 `202403`
- `timelineCardSide`: 枚举，`above | below`
- `timelineAccent`: 枚举或布尔强调态，控制卡片视觉优先级

现有 `timeline[]` 字段继续保留，表示项目内部阶段节点，不直接驱动公开大时间轴位置。

## 页面结构设计

### 顶部工具区

页面顶部采用单行工具条：

- 左侧：返回按钮 + “案例时间轴”
- 右侧：轻量 tab 文案（如 Timeline / Archive / Insights 的中文化等价表达）和分享按钮

顶部工具区只承担导航和状态，不再放置旧版说明侧栏。

### 时间轴画布

画布是页面主角，采用全宽深色网格背景。

结构：

- 中央横向主轴
- 沿主轴排列的年度/季度刻度
- 项目节点落在主轴上
- 项目节点通过垂直引线连接到上方或下方简介卡
- 简介卡交错排布，避免重叠

视觉要求：

- 主轴与引线使用低对比冷色线条
- 当前或强调项目节点可使用更亮的蓝紫色点
- 卡片为半透明深色玻璃面板，保留原型里的悬浮感

### 缩放控制区

右下角保留纵向控件组：

- 放大
- 缩小
- 重置

鼠标滚轮行为：

- 在画布区域内滚轮优先触发缩放
- 缩放以当前视口中心为基准，不做复杂焦点跟随

### 拖拽平移

画布支持按下拖动：

- 默认以横向平移为主
- 允许少量纵向位移缓冲，但不做无限画布
- 松手后停止拖动
- 触控板/鼠标拖拽都应可用

## 响应式规则

- `lg` 及以上：完整横向时间轴画布
- `md` 到 `lg`：保留横向时间轴，但减少卡片宽度与轴间距
- `md` 以下：
  - 仍保留横向滚动时间轴语义，不退化为普通纵向列表
  - 主轴仍然横向延展，用户通过横向拖拽或横向滚动查看时间推进
  - 卡片改为更窄的单列浮卡，但依然通过节点引线挂接在横向主轴上
  - 同一时刻最多突出 1 张主卡，其余卡片缩窄并通过横向位移错开，不做新的移动端列表版
  - 缩放控件仍保留
  - 不强求桌面端同等视觉密度，但必须保留“左到右时间方向”和“节点引线”关系

## 服务与工具函数设计

需要新增或调整的能力：

- 从工作台项目读取公开时间轴条目
- 将项目表单字段映射为公开时间轴所需的统一结构
- 生成连续的年度/季度刻度
- 按年度、季度和卡片上下侧生成节点布局

建议保持职责分离：

- 服务层负责“读到哪些已发布项目”
- 工具函数负责“如何生成刻度、节点和布局”
- 页面层负责“交互状态与渲染”

## 风险与约束

### 1. 现有案例详情仍依赖静态案例数据

处理方式：

- 时间轴页只改数据入口
- 跳转仍通过 `publicCaseId` 复用现有公开案例详情页

### 2. 项目时间字段可能不完整

处理方式：

- 后台编辑页将相关字段设为公开时间轴必填项
- 前台只渲染时间字段完整的项目
- 数据缺失时在工作台层面尽早暴露，而不是前台默默兜底成错误位置

### 3. 拖拽与缩放在测试环境中不易完整覆盖

处理方式：

- 单测锁定 DOM 结构、控件和关键状态
- 交互逻辑拆成可测试的状态更新函数或 hook
- 最后跑真实构建进行手工走查
