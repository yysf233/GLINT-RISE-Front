# 前台 Stitch 高拟真改版设计

**日期：** 2026-03-25

## 背景

当前公开站功能已经基本完整，但整体视觉仍停留在早期深色版本，和 Stitch 原型《企业官网及内部管理系统产品设计全案》中的公开站风格存在明显差距。问题主要集中在以下几类：

- 公开站整体气质和 Stitch 原型不一致，缺少浅底、纸感、技术蓝和编辑式标题体系
- 公共容器、导航、卡片、筛选器、详情信息块没有统一视觉骨架
- 页面之间的层次表达不统一，首页、产品页、案例页的风格割裂
- 当前功能已经闭环，前后台联动、轮播、搜索、分享、权限都已落地，因此改版不能牺牲既有业务能力

## 目标

把公开站改造成高拟真接近 Stitch 原型的浅底蓝系官网，同时保留并验证现有功能完整性：

- 保留所有公开站路由和业务能力
- 保留已经接入 `publicSiteContent` / `publicProductsCatalog` 的前后台同步能力
- 保留搜索、轮播、分享、详情联动和移动端适配
- 把视觉系统、版式结构、模块层次、交互动效改到和 Stitch 原型同一语言

## 非目标

本次不处理以下事项：

- 不重写后台页面风格
- 不替换现有 mock 数据结构
- 不改变公开站 URL 设计和后端契约
- 不把公开站拆成新的路由体系
- 不把案例线和入口页在本次视觉改版中强行改造成后台驱动数据源；这类页面当前仍可继续使用静态内容源

## 设计原则

### 1. 高拟真复刻，功能零退化

页面结构优先向 Stitch 原型靠拢，但任何视觉改版都不能破坏已有功能。所有搜索入口、分享页、轮播自动播放、后台配置同步、案例和产品跳转都必须原样保留。

### 2. 先统一骨架，再逐页收口

先通过公开站专属主题 token 和公共布局收敛视觉语言，再逐页按原型重做结构。主题变量会下沉到 `PageShell` 和公开站根节点，而不是继续挂在整个应用根上，避免误伤后台工作台风格。

### 3. 用“层次”代替“描边”

公开站整体采用 Stitch 设计系统中的“无明显描边分层”规则：

- 通过背景层级区分区块
- 通过留白和阴影做层次
- 通过玻璃和柔和渐变做强调
- 尽量避免高对比度边框

### 4. 公开站桌面与移动端都要像原型

不是单纯把桌面页压缩到手机宽度，而是按原型中移动端的单列节奏、卡片层级和视觉密度重新组织。

## 视觉系统

### 色彩

从当前深色金属风切换到 Stitch 原型中的浅底蓝系体系：

- 页面主底：纸感白与冷灰蓝
- 容器底：不同层级的浅灰白容器
- 品牌主色：技术蓝
- 辅助强调：更亮的蓝色容器和弱高光
- 文本：深灰而非纯黑
- 状态色：沿用现有语义，但降低饱和度，避免破坏整站统一性

### 字体

标题采用更强的 editorial 风格，正文维持清晰阅读：

- 大标题：更强的字号跨度和更紧凑字距
- 小眉标题：高字距全站统一
- 正文：清晰、偏轻
- 数字和短标签：统一成更稳定的 UI 字重

### 组件层次

- 顶部导航：玻璃悬浮感
- Hero：大标题 + 副文案 + 行动区 + 后台驱动的轮播
- 卡片：轻容器、弱阴影、无硬边框
- 搜索和筛选器：浅容器 + 焦点高亮
- 详情页信息块：分组容器，不用深色盒子硬切

## 主题隔离方案

当前仓库的主题变量存在全局根节点上，而后台工作台与公开站共享同一 React 应用。为了满足“只改公开站，不改后台”，本次改版采用以下隔离策略：

- 保留后台现有 Ant Design 工作台主题，不改其 token
- 新增公开站专属主题变量注入层，由 `PageShell` 或公开站根节点负责注入
- `index.css` 只保留全局基础重置，不再承担公开站专属品牌视觉
- 所有浅底蓝系容器、导航、卡片和页面背景都从公开站局部变量读取

这意味着本次改版的第一步不是“全局换肤”，而是“公开站局部换肤”。

## 页面映射

### 公开站全局

- `PageShell`：统一背景、段落间距、入场动效
- `TopNav`：切换成 Stitch 风格玻璃导航，保留右侧搜索框展开交互
- `Footer`：改成浅底信息区

### 首页

首页按 Stitch 首页原型重做：

- 大篇幅 editorial hero
- 后台轮播作为主视觉
- 首页搜索保留
- 特色案例和产品区按策展式层次重排
- 页面留白明显加大

### 产品线

- 产品概览：首屏策展区 + 筛选结果区
- 搜索结果：更强的信息密度和筛选器表达
- 热门产品：沿用原型里的策展列表和模块节奏
- 产品详情：大图主视觉 + 分组说明 + 参数区块
- 产品分享：轻量但和主站同体系

### 案例线

- 案例总览：大图和信息区交错布局
- 案例详情：章节式叙事
- 时间轴：保留真实时间轴功能，但视觉对齐原型
- 图谱：保留功能但改成更轻、更规整的展陈方式
- 分享页：移动端优先、轻量层级

### 入口页与登录页

- 入口页切换到浅底品牌入口
- 登录页沿用浅底品牌风格外壳，保留现有登录逻辑

## 执行顺序

### 第 0 阶段：公共层

- 重写公开站 token
- 重做 `PageShell` / `TopNav` / `Footer`
- 重做通用标题、卡片、搜索条、标签等公共组件

### 第 1 阶段：首页

首页是视觉锚点，先改它来验证新主题是否成立，并顺带验证轮播、搜索、推荐模块不退化。

### 第 2 阶段：产品线页面

- 产品概览
- 搜索结果
- 热门产品
- 产品详情
- 产品分享

### 第 3 阶段：案例线页面

- 案例总览
- 案例详情
- 案例时间轴
- 案例图谱
- 案例分享

### 第 4 阶段：入口页与登录页

最后收口入口和登录，避免前台主路径风格断裂。

## 验收策略

每个页面改完后，都执行同一套节奏：

1. 先补页面相关的失败断言
2. 对已有纯函数、静态结构或 test hook 使用 Vitest
3. 对页面交互、搜索、轮播、后台同步和跨页流程，使用 `scripts/verify-pages.mjs` 中的浏览器回归断言
4. 跑 `npm run build`
5. 对照改版前的功能清单逐项检查：搜索、跳转、分享、轮播、后台同步、移动端适配

全部页面改完后，再做一轮公开站总回归，重点覆盖：

- 已接入后台驱动的首页和产品线页面在后台改信息后同步是否准确
- 轮播自动切换是否仍然稳定
- 页面切换和关键交互动效是否合理
- 权限边界是否没有被公开站改版影响

## 风险与控制

### 风险 1：公共层改动波及所有页面

控制方式：先补公共层相关测试和路由回归断言，再改页面本身。

### 风险 2：高拟真复刻导致功能元素丢失

控制方式：每页在改写前先列功能保留清单，改完后逐项复核。

### 风险 3：移动端被桌面布局挤压

控制方式：按原型的移动端节奏单独调整，而不是仅靠响应式缩放。

## 结果定义

当以下条件同时满足时，本次公开站改版视为完成：

- 公开站所有现有页面均切换为 Stitch 浅底蓝系视觉语言
- 所有现有公开站功能仍然可用
- 前后台联动链路没有断
- 单测、构建、浏览器回归全部通过
