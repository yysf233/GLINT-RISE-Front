# Case Timeline Design

**Date:** 2026-03-23

## Goal
补齐 `PRJ_PRD.md` 中“项目时间轴 / 案例列表页”的真实界面实现，在保留当前 `#/cases` 案例总览页与 `#/case-map` 案例图谱页的前提下，新增一个可独立访问、可用于客户展示的 `#/case-timeline` 项目时间轴页。

## Approved Direction
- 保留当前 `#/cases` 作为“案例总览页”
- 新增 `#/case-timeline` 作为“项目时间轴页”
- 主导航采用双入口并存：`案例总览`、`项目时间轴`
- `#/case-map` 继续保留为案例模块的独立可视化入口
- 时间轴页采用纵向叙事式时间线，而不是筛选页式列表或左右分栏索引页
- 时间轴页需要同时服务 PC 与移动端，移动端保持单列纵向阅读

## Scope
本次只处理公开站案例模块，不处理后台项目管理功能，不接真实接口，不新增独立移动站，不重写现有案例详情页结构。

本次范围包括：
- 新增 `#/case-timeline` 路由与页面
- 更新主导航，暴露“案例总览”与“项目时间轴”两个一级入口
- 在案例总览页中增加进入时间轴页的导流入口
- 使用现有 `cases` 内容数据驱动时间轴分段与案例节点
- 更新 `PRJ_PRD.md` 的当前实现口径与推进状态
- 更新自动验收脚本，覆盖时间轴页访问与跳转

本次不包含：
- 后台项目录入、编辑、发布能力
- 时间轴筛选、搜索、排序等管理型能力
- 案例详情页大规模改版
- 真实分享落地页

## Information Architecture
- `#/cases`：案例总览页，继续承担首屏策展浏览
- `#/case-timeline`：项目时间轴页，承担按时间叙事浏览案例的职责
- `#/case-map`：案例图谱页，承担关系可视化浏览
- `#/case/:id`：案例详情页，承担单案例详情展示

导航口径：
- 主导航并列展示 `案例总览` 与 `项目时间轴`
- 时间轴页首屏提供跳转按钮：
  - `查看案例总览`
  - `进入案例图谱`
- 时间轴节点卡片点击后进入对应 `#/case/:id`

## Timeline Page Structure
页面结构建议维持和现有公开站一致的视觉语言，不单独发明新设计系统。

1. 首屏区
- 标题明确为“项目时间轴”或同等中文命名
- 一段说明文案，解释该页按时间沉淀案例
- 两个辅助入口按钮：返回案例总览、进入案例图谱

2. 时间轴主体
- 采用纵向主轴线
- 以时间分段组织内容，优先复用当前案例数据中的 `year`
- 如果已有值包含季度信息（如 `2024.Q1`），则按该粒度展示；只有年份时按年份展示
- 每个时间段下展示对应案例节点卡片

3. 案例节点卡片
- 展示时间标签
- 展示案例标题与摘要
- 展示行业、子标签等轻量信息
- 提供进入详情按钮或整卡点击跳转
- 卡片风格应与当前案例模块卡片体系保持一致

4. 移动端策略
- 时间轴改为单列纵向堆叠
- 不使用横向滚动时间轴
- 顶部说明和两个辅助按钮保持可点击与可换行

## Data Model
当前 `cases` 数据已经包含以下可直接复用字段：
- `id`
- `title`
- `summary`
- `industry`
- `subTags`
- `year`
- `hero`

为减少改动，本次优先复用现有字段，不要求单独新建复杂数据模型。实现时可增加轻量辅助逻辑：
- 基于 `year` 生成排序键
- 基于 `year` 生成时间分段
- 按时间从近到远排序

如果实现过程中发现仅靠 `year` 无法稳定排序，可以为案例数据补充最小字段，例如 `timelineOrder`，但应保持数据改动最小。

## Behavior
- 用户可以从主导航直接进入 `#/case-timeline`
- 用户可以从 `#/cases` 进入 `#/case-timeline`
- 用户可以从 `#/case-timeline` 返回 `#/cases` 或进入 `#/case-map`
- 用户可以从任意时间轴节点进入对应案例详情页
- 刷新 `#/case-timeline` 后应保持在当前路由
- 时间轴页不引入额外客户端状态管理，使用静态内容数据直出

实现完成后，`PRJ_PRD.md` 需要同步回填以下口径：

- 页面可访问并正常渲染
- 页面中能识别时间分段或时间标签
- 页面中存在至少一个可进入案例详情的节点
- 时间轴页加入整体路由回归、刷新保持与前进后退检查

## Risks And Constraints
- 当前案例数据条数较少，时间轴页的叙事层次会偏轻；页面结构需要允许未来继续扩展
- 主导航增加一级入口后，桌面端与移动端导航宽度都要重新验证
- `year` 字段当前格式并不完全统一，排序逻辑需要对 `2024` 与 `2024.Q1` 兼容处理
